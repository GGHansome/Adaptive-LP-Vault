# 前端实现与维护

## 技术与目录

前端为 React + TypeScript + Vite 客户端应用，采用 Ant Design、wagmi、viem、TanStack Query 和 Zustand。业务读写直接访问公开 RPC 与钱包，不引入业务后端、数据库或托管签名服务。架构约定见 [`../FRONTEND_ARCHITECTURE_PROMPT.md`](../FRONTEND_ARCHITECTURE_PROMPT.md)。

- `src/main.tsx`：挂载应用与全局样式。
- `src/App.tsx`：六个路由的懒加载与组合；账户、网络或部署变化时重建交易表单及预览。
- `src/providers/AppProviders.tsx`：集中配置钱包、稳定的 QueryClient、主题、通知与路由 Provider。
- `src/features/containers/<Name>Container/`：业务容器；`server-store/selector.ts` 组合读取和展示模型，`mutation.ts` 解析输入并提供业务动作。容器不直接拼接合约请求。
- `src/features/components/<Name>/`：Vault 展示组件，只接收明确的 Props 与语义回调；不读取钱包、查询缓存或 Zustand。
- `src/features/containers/server-store/`：各业务容器共用的查询定义、缓存键、部署校验、区块快照及交易基础 Hook；各容器内部的 `server-store/` 保留页面专属的数据组合与业务动作，查询仍由页面按需启用。
- `src/features/types.ts`、`utils/`：领域模型与纯计算。Manager 和 Guardian 通过公共 `ControlsContainer` 入口复用安全控制，不导入彼此页面内部实现。
- `src/shared/components/`、`utils/`：跨页面的业务无关展示、布局、表单及纯格式化。
- `src/shared/store/transactionStore.ts`：Zustand 交易进度与原子提交锁；消费方按字段订阅。
- `src/shared/web3/`：通用交易执行与错误转换；不反向依赖 Vault。
- `src/config/`：公开配置及部署清单校验。默认连接 chainId 31337 的 Anvil；`VITE_RPC_URL` 是公开端点，不得包含私钥或秘密凭据。
- `src/contracts/index.ts`：ABI 公共入口，引用 `src/generated/abi.ts`。运行 `npm run abi` 生成接口，禁止手改签名。
- `src/generated/deployment.json`：本地部署工具生成、被 Git 忽略的公开清单，不包含私钥；保留原输出路径以兼容部署和端到端工具。

当前业务直接放在 `src/features/` 下，按组件、容器、远端访问层、类型与工具划分职责，保持这一层级即可。

复用组件采用具名导出、同名目录与显式入口，边界 Props 放在 `interface.ts`。`npm run lint` 检查展示层对钱包、Store、请求及业务基础设施的依赖，禁止公共层反向依赖 feature，并约束容器内的直接网络与合约调用。静态规则不能代替代码审查，不得通过间接封装绕过分层。

## 状态归属与订阅

原 `SessionContext` 和聚合式 `useSession()` 已移除，状态按来源分配：

- **链上事实由 TanStack Query 管理**：公共快照、账户余额与授权、账户权限、事件、管理员交接与角色成员使用不同缓存键。公共查询不依赖账户；账户查询按部署实例、目标链、合约和地址隔离。
- **共享客户端过程由 Zustand 管理**：只保存交易标识、原始提交身份、阶段、哈希、错误及忙碌状态。页面操作只订阅 `busy`，交易提示单独订阅进度；不复制余额、角色、wagmi 客户端或整个查询对象。
- **本地交互就近管理**：表单草稿、确认弹窗和安全控制草稿留在组件或最近容器中。
- **预览是按需查询**：键包含身份、表单参数和显式请求序号。修改表单或切换身份后不展示旧结果，迟到响应只能更新自己的缓存条目。

部署验证检查 RPC 网络、部署区块哈希、Vault 代码及 Control、Oracle、Token 绑定，是业务读取与写入的前置条件。公共估值所需的资产、价格、仓位与暂停状态固定在同一区块读取；固定策略参数单独缓存。

当前本地环境的动态快照、余额、权限、交接状态与部署验证每 3 秒检查；最近事件每 6 秒读取；管理员成员仅在已确认的管理员页面启用，每 30 秒核对。成员查询键不包含区块号，避免为每个区块建立完整历史扫描缓存。固定参数在当前部署实例内长期缓存。这些间隔适用于本地联调，不是生产网络策略。

权限读取区分未连接、未就绪、成功与失败；刷新失败立即撤销界面的已确认权限。角色成员或最近事件失败只影响对应区域，不阻断其他业务。界面门禁不代替合约权限检查。多角色权限取并集，根管理员不隐含业务角色。

## 交易与失败恢复

功能 mutation 对展示层暴露存款、赎回、授权、再平衡、初始化和角色管理等动作。金额以字符串输入、按实际 decimals 转为 `bigint`；精确计算不经过浮点数。

统一执行顺序：输入检查 → 获取原子提交锁 → 校验当前身份 → 模拟合约 → 再次校验账户与网络 → 钱包签名 → 按原客户端等待回执 → 成功后刷新受影响查询。初始化的两次授权和一次 Bootstrap 共用一个业务锁，中间不允许其他交易插入。

- 模拟失败、拒签或已确认回滚会显示原因并恢复操作；不自动重复发送交易。
- 已取得哈希但回执查询失败时，显示“确认状态未知”，保留提交锁。通过交易提示中的“重新查询确认”继续跟踪原哈希，确认成功或回滚后才解锁。
- 切换账户不会取消已发送交易的确认过程；提示保留提交账户，确认后的失效范围仍按原部署与业务影响计算，不将原账户结果写入新账户。
- 成功回执后按动作刷新余额、授权、仓位、权限或事件；代币授权不触发公共快照及其他账户的无关刷新。刷新失败不会把已成功交易误报为回滚。
- 交易通知在执行层统一处理；业务校验与提交错误供表单显示，避免重复弹出相同失败通知。
- 交易过程仅保存在当前页面会话内，不持久化签名能力或执行客户端。刷新页面后，应先核对钱包交易记录及链上回执，避免重复提交未确认操作。

存款前分别授权两种资产，默认授权精确输入上限。存取款必须显式预览；最低输出来自模拟值和用户选择的滑点。赎回预览直接模拟合约，不依赖 Oracle 估值，因此暂停、IDLE 或预言机不健康不额外关闭赎回。

再平衡预览仅提供计划、换币需求及方向，不推导“最优换币数量”。有效期和冷却使用链上时间；活跃仓位按策略撤至 EXTREME/IDLE 时豁免冷却，重新入场仍需等待。提交前重新核对计划哈希与方向，失败不降低协议最低输出保护。模拟和签名之间仍可能发生状态变化，最终约束由合约执行。

## 布局与展示口径

布局优先采用 Ant Design 的 `Layout/Sider/Header/Content/Footer`、`Menu`、`Breadcrumb`、`Flex`、`Row/Col`、`Space`。保留深色常驻 sidebar，主题颜色与圆角由 Provider 配置。全局 CSS 仅保留基础重置和少量公共尺寸，应用外壳样式在 `Shell/Shell.css`；不维护另一套手写网格和导航组件。

- 桌面显示完整侧栏，滚动页面时导航保持可见；窄屏缩为常驻图标栏，直接点击图标切换页面，不使用抽屉导航。
- 内容区域继续使用卡片堆叠、按钮换行和表格横向滚动。
- 净资产和单份额净值以实际 token1 计价，不假定美元价格。
- Oracle 不健康时隐藏价格、偏离和估值，不将无效零值显示为真实市场数据。
- 已执行策略与实时信号分别展示；刷新预览不会提交新策略版本。
- V2 手续费计入储备权益；V3 展示仓位快照的可领取费用。
- 最近事件仅覆盖最近 500 个区块、最多 12 条；管理员成员从部署区块开始分段发现授权地址，再用 `hasRole` 核实当前权限。

## 开发与验证

在仓库根目录运行 `npm run dev`、`npm run lint`、`npm test`、`npm run build`。构建先运行 `npm run abi`。格式检查使用 `npm run format:check`；完整钱包联调见 [`../contract/local/README.md`](../contract/local/README.md)。生产密钥、可签名的测试钱包适配器不得进入浏览器运行时代码。

本次重构验证：

- 前端自动测试覆盖金额精度、权限门禁、查询依赖、账户缓存隔离、非关键查询失败、迟到预览、Zustand 细粒度订阅、原子锁、拒签、回滚、回执查询失败与重新确认，以及按业务刷新缓存。
- 类型检查、ESLint 和生产构建通过；Vite 仍提示 viem 的间接依赖 `ox` 引用的 `node:worker_threads` 被浏览器构建外部化。
- 目录扁平化与常驻侧栏调整后，39 项前端测试及 4 项合约工具测试通过；新增侧栏常驻、图标导航及钱包入口回归测试。
- 使用本地测试钱包适配器完成六个页面的只读浏览器检查，在 1440px／940px／390px 下验证侧栏常驻、图标导航、滚动时保持可见及无横向溢出，无浏览器运行时异常。
- `npm run test:e2e` 已完成浏览器双资产授权、预览及存款；后续启动行情模拟时检测到已有持续交易进程而中断，测试脚本已恢复本地链快照。完整的赎回、再平衡执行、角色写入、安全控制与移动端端到端链路仍需在停止行情进程后重新运行；本次未停止用户的持续交易进程。

路由、权限、合约方法、状态归属或展示口径变化时，同步本说明和相应测试。新增功能遵循架构规范，不恢复集中式会话 Store。
