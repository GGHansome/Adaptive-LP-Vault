# 受控换币再平衡：建议金额

状态：待审阅。本文描述拟新增的前端辅助功能。换币权限、部署比例与执行约束仍以 [协议规格](../../../contract/docs/PRODUCT_SPEC.md) 为准。

## 目标与边界

当前预览返回候选计划、是否需要换币及方向，不返回金额。Keeper 或 Manager 即使知道要将 `tETH` 换成 `tUSD`，仍可能因为换得太少或太多反复试错。在现有「受控换币再平衡」表单增加「计算建议金额」，提供在某一链上快照下可通过整笔模拟的输入，并尽量减少预计闲置资产。

第一版只改前端。无需修改合约、ABI、链上权限或部署配置，也不引入报价服务、自动 Keeper、自动签名或自动发交易。建议金额不保证全局最优、后续成交或收益，不代替现有的手动输入与钱包确认。

## 交互与失效条件

- 连接正确部署和网络、确认拥有 Keeper 或 Manager 角色、预言机健康、有未过期且需要换币的候选计划、换币未暂停且冷却结束时，可计算建议金额。计算期间禁用重复请求和换币提交；失败后可重试或继续手动填写。
- 使用当前「调用者最低输出」参与验证；计算不更改该字段，包括默认的 `0`。最低输出不合法时先提示修正。协议自身的最低输出保护仍由合约执行。
- 成功后显示建议金额及其币种，用户点击「填入」只写换币输入，仍可手动修改。没有可用候选或 RPC 读取失败时，不填入金额，也不清空用户已有的输入；分别提示刷新后重试或检查连接。
- 建议绑定部署、账户、链、计划哈希、方向、最低输出和计算区块时间。计划刷新、账户或部署切换、最低输出变化、过期或前置条件失效时，丢弃旧建议和仍在途的旧结果。填入前核对绑定；计算期间如果候选计划变化，不展示旧结果。已填入的金额只是表单输入，不缓存为可执行授权。
- 提交沿用现有路径：重新预览并检查计划、重新模拟交易，再由钱包确认。计算或填入均不会打开钱包。

## 估算与验证

1. 从同一已出块区块读取 Vault 的双资产总额（含可领取费用）、候选计划、预言机长周期均价、换币滑点参数及目标适配器配置。再次核对当前候选与页面计划一致。计算全部用最小代币单位和整数。
2. 在 `0 < amountIn <= 输入币余额` 的范围内，用预言机与协议滑点参数估算保守输出；用目标适配器的 `previewDeposit` 估算扣除输入、加入输出后的可部署资产。先按剩余资产的方向找比例附近的候选，再试附近较少和较多的金额；按长周期均价折算预计闲置价值占比，从低到高选候选。这个排序只是估算，不是实际成交报价；不假定整笔交易的成功区间可以二分。每次请求最多评估 24 个金额、完整模拟 8 个金额；候选已去重且在余额范围内，到预算上限即停止，不无界重试。
3. 对排序后的候选，用已连接账户在同一区块通过只读调用模拟 `rebalanceWithSwap`，传入预览方向、哈希、计算出的输入和表单最低输出。只推荐首个通过完整模拟的候选；候选金额模拟失败时可试下一个，但 RPC 失败单独报告，不能当作金额不可执行。该调用同时验证合约的资产部署比例、换币方向、滑点、迁移损失和资产守恒等约束。
4. 完成后复核最新的计划及其有效性。即使通过计算时的模拟，提交仍以提交时的重新模拟和链上执行为准。

单独做本地数学估算会把未经过真实路由与协议检查的金额交给操作人；本方案用全交易模拟兜底。把求解放进合约或部署报价器可以提供共享接口，但会增加部署面和维护成本，对当前人工操作不是必需的。前端方案的代价是按需消耗若干 RPC 调用，且可能找不到本来存在的可执行金额；此时保留人工路径，不放宽协议限制。

## 验收与文档同步

- 测试两种换币方向、两种代币精度不同、余额约束、候选去重和请求预算。验证优先使用预计闲置占比较低且完整模拟通过的金额；覆盖候选回退、无可用金额和网络失败。
- 测试非 Keeper/Manager、过期计划、计划或账号变化、最低输出变化和并发结果失效。校验「填入」只修改金额，未触发钱包；提交仍进入原有模拟和钱包流程。
- 用本地 `shock` 场景人工或端到端验证旧 V3 区间已经越界、规划仍是同一池的新区间时，Keeper 可以取得建议并填入；验证链上的区间和余额在只读计算后未改变。验收不固定建议金额，因为链状态会变化。
- 功能交付时同步本地联调说明，区分「只读建议金额」与「自动求全局最优或自动执行」；不改变协议规格中的约束。
